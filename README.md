# MemBomb

Лабораторная работа №2 по операционным системам: выделение памяти страницами до отказа,
график свободной ОЗУ, OOM Killer в Linux и отказ `VirtualAlloc` в Windows.
Один исходник на C (`src/membomb.c`) собирается под Linux (`mmap`) и под Windows (`VirtualAlloc`).

> Запуск без ограничений (`-m 0`) исчерпывает всю память. Запускать в виртуальной машине
> или с квотой, не на рабочей системе.

## Состав

| Путь | Назначение |
| --- | --- |
| `src/membomb.c` | Единственный исходник: выделение/касание страниц, замер свободной памяти, CSV/SVG |
| `src/free_memory.csv` | Пример ряда свободной памяти с прогона (Windows, 2 ГБ) |
| `src/free_memory.svg` | Построенный по этому ряду график |
| `Makefile` | Сборка под Linux (`membomb` и `membomb_raw`) |
| `compile.bat` | Сборка под Windows (MinGW `gcc`) |
| `docs/otchet.md` | Полный отчёт по лабораторной с результатами прогонов |

## Требования

- C-компилятор: `gcc` (MinGW-w64 на Windows) или `clang`.
- Для Linux-эксперимента с OOM — виртуальная машина и права `sudo` (для `swapoff -a`).

## Сборка

Linux:

```bash
make                 # соберёт src/membomb и src/membomb_raw
```

Windows (MinGW):

```bat
compile.bat
```

или вручную:

```bash
gcc -Wall -O2 -o src/membomb src/membomb.c
gcc -Wall -O2 -DMEMBOMB_RAW -o src/membomb_raw src/membomb.c
```

## Запуск

| Команда | Что делает |
| --- | --- |
| `./membomb` | Выделяет память до отказа, пишет `last_moments.csv` |
| `./membomb -m 2048 -s 8` | Выделить и коснуться 2048 МБ, шаг замера 8 |
| `membomb.exe -safe -m 2048 -s 8` | Выделить, подержать, освободить, записать `free_memory.*` |
| `membomb.exe -safe -q 64 -m 0 -s 2` | Windows: квота Job Object 64 МБ, отказ `VirtualAlloc` без зависания машины |
| `./membomb -plot` | Построить график из последнего CSV |
| `membomb_raw` | Тот же код без записи файлов (для «голой» ВМ) |

Ключ `-safe` включает сценарий с удержанием и освобождением; `-q N` в Windows ставит
квоту commit charge; `-m 0` снимает лимит (полное исчерпание).

## Результаты

- Шаг равен размеру страницы (4096 байт). `mmap` и `VirtualAlloc` создают только виртуальный
  регион, физический кадр появляется при первом обращении (demand paging). Поэтому в каждую
  страницу программа записывает байт, иначе свободная ОЗУ почти не меняется.
- График (Windows, ~32 ГБ): после касания 2 ГБ свободная физическая память упала примерно на
  2 ГБ и вернулась после `VirtualFree`. Форма: плато, спуск, удержание, подъём.
- Windows не убивает процесс: при исчерпании commit charge `VirtualAlloc` возвращает `NULL`,
  `GetLastError()=1455` (`ERROR_COMMITMENT_LIMIT`, «файл подкачки слишком мал»).
- Linux при overcommit по умолчанию не возвращает ошибку из `mmap`. Ядро выбирает процесс по
  `oom_badness` и шлёт ему `SIGKILL` (OOM Killer — часть ядра, не демон). `swapoff -a` отключает
  swap, чтобы OOM наступал сразу, а не после нескольких минут thrashing.

Команды, выводы и источники — в [`docs/otchet.md`](docs/otchet.md).

## Ограничения

- Программа работает только в своём процессе. В Linux его убивает OOM Killer, память возвращается системе.
- Квоты и лимиты ОС не обходятся, программа показывает, как они срабатывают.
- Без лимита `-m` или квоты на рабочей машине не запускать.
